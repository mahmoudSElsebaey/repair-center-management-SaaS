# دليل استخدام منصة RepairFlow

**دليل شامل بالعربية — يشرح المنصة، الهدف منها، الأدوار، والميزات، وكيفية الاستخدام خطوة بخطوة.**

---

## 1. ما هي منصة RepairFlow؟

**RepairFlow** منصة تشغيل متكاملة لمراكز صيانة وإصلاح الأجهزة (هواتف، لابتوب، أجهزة منزلية، تكييف، وغيرها).

تغطي المنصة دورة العمل الكاملة من استلام الجهاز حتى التسليم والضمان، مع دعم:

- إدارة العملاء والأجهزة
- تذاكر الإصلاح ومراحل الحالة
- الفنيين والموظفين والصلاحيات
- المخزون وقطع الغيار
- عروض الأسعار وموافقة العميل
- الفواتير والمدفوعات
- تتبع عام للعميل عبر رمز QR
- جدولة المواعيد
- التقارير والإحصائيات
- الإشعارات وسجل النشاط
- واجهة ثنائية اللغة (عربي / إنجليزي) مع دعم كامل لاتجاه RTL

التقنية: تطبيق **MERN** (MongoDB · Express · React · Node.js) مع TypeScript و Tailwind.

## 4. نظرة عامة على أقسام النظام

### 4.1 الموقع التسويقي (عام)
- صفحة تعريف بالمنصة
- تسجيل الدخول للموظفين
- **تتبع عام للعميل:** `/track` و `/track/رمز-التذكرة`

### 4.2 لوحة التشغيل (بعد تسجيل الدخول) `/app`

| القسم | ماذا يفعل |
| ----- | --------- |
| **لوحة التحكم (Dashboard)** | أرقام حية: تذاكر مفتوحة، إيرادات، نشاط حديث |
| **العملاء (Customers)** | إضافة/بحث/تعديل العملاء وربط الأجهزة |
| **الأجهزة (Devices)** | تسجيل الجهاز، الرقم التسلسلي، الموديل |
| **التذاكر (Repairs)** | فتح تذكرة، مراحل الحالة، التشخيص، التكاليف، الجدول الزمني |
| **الفنيون والموظفون (Staff)** | حسابات، أدوار، حمل العمل على الفنيين |
| **المخزون (Inventory)** | أصناف، حركات (شراء/استخدام/إرجاع/تعديل)، تنبيه نقص |
| **عروض الأسعار (Quotations)** | بنود عمالة + قطع، إرسال للعميل، موافقة أو رفض |
| **الفواتير (Invoices)** | إصدار من تذكرة معتمدة، حالة الفاتورة، الإبطال |
| **المدفوعات (Payments)** | تسجيل دفعة جزئية أو كاملة وربطها بالفاتورة |
| **المواعيد (Appointments)** | تقويم أسبوعي، تعيين فني، منع التعارض |
| **التقارير (Reports)** | إيرادات، طرق دفع، حالات، أداء فنيين، فترة زمنية |
| **سجل النشاط (Activity)** | أثر تدقيقي: من فعل ماذا ومتى |
| **الإشعارات (Notifications)** | تنبيهات للأدوار المناسبة حسب الفرع |
| **الإعدادات (Settings)** | تفضيلات الحساب والواجهة |

## 5. التدفق التشغيلي المعتاد (من الاستلام حتى التحصيل)

```
1) استقبال العميل
      ↓
2) إنشاء / اختيار عميل + تسجيل الجهاز
      ↓
3) فتح تذكرة إصلاح (Repair)
      ↓
4) تشخيص وتقدير تكلفة (اختياري: عرض أسعار)
      ↓
5) إرسال عرض الأسعار → موافقة العميل (أو رفض)
      ↓
6) تنفيذ الإصلاح وتحديث الحالات
      ↓
7) إصدار فاتورة
      ↓
8) تسجيل المدفوعات حتى سداد الرصيد
      ↓
9) تسليم الجهاز + إمكانية الضمان لاحقاً
```

**تتبع العميل في أي وقت:**  
افتح الرابط العام  
`/track/RF-YYYY-#####`  
أو امسح رمز QR من صفحة تفاصيل التذكرة — **بدون تسجيل دخول**.

## 6. كيفية الاستخدام — خطوة بخطوة

### 6.1 تسجيل الدخول
1. افتح الموقع.
2. اضغط **تسجيل الدخول / Login**.
3. أدخل البريد وكلمة المرور.
4. بعد النجاح تُفتح لوحة التشغيل `/app`.

يمكنك تبديل اللغة **عربي ⇄ English** من الواجهة؛ الاتجاه يتغير تلقائياً (RTL/LTR).

### 6.2 إضافة عميل وجهاز
1. من القائمة: **العملاء**.
2. **إضافة عميل** — الاسم، الهاتف، ملاحظات.
3. من بطاقة العميل أو قسم الأجهزة: **إضافة جهاز** (النوع، الموديل، الرقم التسلسلي إن وُجد).

### 6.3 فتح تذكرة إصلاح
1. **التذاكر → تذكرة جديدة**.
2. اختر العميل والجهاز، وصف العطل، الأولوية إن لزم.
3. يُنشأ رمز تلقائي مثل `RF-2026-00042`.
4. حدّث الحالة عبر أزرار سير العمل (استلام → تشخيص → انتظار قطع → قيد الإصلاح → … → جاهز / مسلّم).

### 6.4 عرض الأسعار وموافقة العميل
1. من تفاصيل التذكرة: أنشئ **عرض أسعار** وأضف بنود العمالة والقطع.
2. **إرسال للموافقة** — تتغير حالة التذكرة إلى انتظار العميل.
3. عند الموافقة أو الرفض تتحرك التذكرة وفق سير العمل.

### 6.5 الفاتورة والدفع
1. بعد الاعتماد: **إصدار فاتورة** من التذكرة/العرض.
2. من **الفواتير** أو تفاصيل الفاتورة: **تسجيل دفعة** (مبلغ، طريقة الدفع).
3. يتحدث الرصيد المستحق حتى السداد الكامل أو إبطال الفاتورة عند الحاجة (مع صلاحية مناسبة).

### 6.6 المواعيد
1. **المواعيد** → اختر يوماً من الأسبوع.
2. أنشئ موعداً: عميل، وقت، فني اختياري.
3. النظام يرفض التعارض إذا كان الفني مشغولاً في نفس الفترة.

### 6.7 المخزون
1. **المخزون** → أضف صنفاً (SKU، كمية، حد أدنى).
2. سجّل حركة: شراء، استخدام على تذكرة، إرجاع، أو تسوية.
3. عند انخفاض الكمية تحت الحد يصل تنبيه لمدير المخزون.

### 6.8 التقارير
1. **التقارير**.
2. اختر الفترة (7 / 30 / 90 يوماً أو مخصص).
3. راجع الإيرادات، توزيع طرق الدفع، حالات الفواتير والتذاكر، وأداء الفنيين.

### 6.9 التتبع العام للعميل (بدون حساب)
1. من تفاصيل التذكرة انسخ الرابط أو اعرض **QR**.
2. العميل يفتح الرابط ويرى: الحالة، الجهاز، الفرع، ومسار التقدم — **بدون بيانات مالية داخلية حساسة**.

### 6.10 الإشعارات وسجل النشاط
- **الإشعارات:** فلترة حسب النوع، وضع كمقروء.
- **سجل النشاط:** بحث، فئة، من تاريخ → إلى تاريخ — للمراجعة والتدقيق.

## 7. حالات تذكرة الإصلاح (ملخص)

الحالات تتقدم وفق جدول سير عمل على الخادم، ومن الواجهة تظهر أزرار الانتقال المسموحة فقط حسب الحالة الحالية والصلاحية، مثل:

- مستلمة / قيد التشخيص  
- انتظار موافقة العميل  
- معتمدة / مرفوضة  
- انتظار قطع غيار  
- قيد الإصلاح  
- جاهزة للتسليم  
- مُسلَّمة / ملغاة  

كل انتقال يُسجَّل في **الجدول الزمني** داخل التذكرة وفي **سجل النشاط**.

## 9. نصائح سريعة للموظفين

| نصيحة | السبب |
| ----- | ----- |
| ابحث بالهاتف أو الاسم قبل إنشاء عميل جديد | تجنب التكرار |

## 10. التشغيل المحلي (للمطورين)

```bash

cd server && npm install && cp .env.example .env

cd server && npm run seed
```

```bash
npm run typecheck
npm run verify:i18n
curl http://localhost:5000/api/v1/health
```

## 11. الأمان والصلاحيات (باختصار)

- الدخول عبر JWT (رمز وصول قصير العمر + تجديد).
- كل عملية حساسة تمر عبر صلاحية الدور + نطاق الفرع (ما عدا Super Admin).
- الواجهة العامة للتتبع مُقيَّدة المعدل (rate limit) ولا تعرض بيانات داخلية حساسة.
- في بيئة الإنتاج: رؤوس أمان، حدود طلبات، وفحص جاهزية قاعدة البيانات.
